# 操作指南与实现边界

先完成 [安装说明](INSTALL.md)。以下描述对应本仓库的 Streamlit 采集路径；底层插件、ROS 话题和参数定义见 [系统结构与源码索引](ARCHITECTURE.md)。

## 设备启动与扫描

1. 确认三路相机的有效路径分别对应顶部、左腕和右腕。界面可修改 auto/manual 模式与手动兜底路径，稳定绑定需编辑本地 JSON。空闲预览向相机请求 640 × 480、30 fps，预览线程以 20 Hz 为目标读取并缩小到 320 × 240；网页面板每 0.5 秒刷新。`preview_capture_fps` 是预览线程测得的读取频率。
2. 确认 CAN 脚本的 USB 端口映射与本机一致，接口为 `can_left`、`can_right`，速率为 1 Mbps。
3. 点击 **启用设备**。实际顺序为检查已有进程、激活 CAN、启动 IK、双臂控制、XR 服务、bridge，等待 2 秒后扫描；中途失败会返回已执行步骤，先检查其日志。
4. 查看扫描详情后进入 **数据采集**。启动采集的必要检查是两个 CAN、三路相机、bridge、左右臂反馈。左右臂的关节、TCP、夹爪反馈均需小于 100 ms；VR 和 IK action 的 500 ms 检查是提示项，未进入总 `scan.ok` 的必要条件。扫描通过不代表手柄输入或 IK 目标一定正常。

**设备失能**停止预览、telemetry 和界面管理的 bridge/XR/IK/双臂进程；界面检测到的外部进程会保留，CAN 接口也不会被关闭。这一按钮不等于硬件急停或断电。

**一键优化设备进程**需要勾选确认，采集活跃时拒绝执行。它会清理 bridge、IK、双臂控制进程，包括外部启动的对应进程，再启动这些组件；不会清理或重启 XR 服务。**恢复 Bridge/VR 状态读取**尝试补启缺失的 bridge/XR；采集页在活跃阶段也会执行节流后的恢复检查。这些操作不保证修复所有硬件故障。

实现：[runtime.py](../pico_piper_streamlit_app/runtime.py)、[process_manager.py](../pico_piper_streamlit_app/process_manager.py)、[device_scan.py](../pico_piper_streamlit_app/device_scan.py)。

## 一阶段、多条 episode

| 配置 | 默认值／含义 |
| --- | --- |
| 保存根目录 | `/projects/lerobot/NX/data`，可在界面修改 |
| Dataset name | 与根目录拼接为新目录；已存在的路径不能继续写入 |
| Task | 写入该阶段数据的任务描述 |
| 单条时间 | 30 秒，可调整 |
| 重置时间 | 10 秒，可调整为 0 |
| 开始倒计时 | 每轮 5 秒 |
| 录制目标 | 30 Hz，三路相机默认请求 640 × 480、30 fps |
| 视频 | H.264，保存／结束时等待编码与元数据收尾 |
| 远程上传 | 关闭；`zme/<dataset_name>` 是继承的本地 LeRobot 标识，不代表用户账号或上传操作 |

点击 **开始阶段采集**后，界面先扫描必要设备，再停止空闲预览以释放相机，创建数据集并连接采集插件，然后进入倒计时与录制。连接失败可能已留下部分目录；检查后使用新名称重试，不要把部分目录当作已完成数据集。

录制到时，或点击 **结束当前条并进入确认**，会先经过环境重置等待，再出现保存／丢弃选项。重置等待不写数据帧，遥操链路仍可运行，不会自动归位或暂停机械臂。**机械臂复位**按钮只报告尚未实现，不发送运动指令。

| 操作 | 结果 |
| --- | --- |
| 保存并继续采集下一条 | 保存当前 episode，下一条仍写入本阶段同一数据集 |
| 保存并结束当前阶段 | 保存当前 episode，结束阶段并收尾 |
| 丢弃并重采当前条 | 清除当前缓冲区，重采当前 episode |
| 丢弃并结束当前阶段 | 清除当前缓冲区，结束阶段并收尾 |
| 录制时点击“丢弃当前条重采” | 立即丢弃当前缓冲区，经重置后重新倒计时；不会再弹出该条保存确认 |
| 录制时点击“结束阶段采集” | 提前结束当前条，经重置和人工保存／丢弃确认后结束阶段 |

`SAVING`、`DISCARDING`、`FINALIZING`、`CLEANING_UP` 期间等待收尾，直到状态为 `DONE` 且线程退出后再开始新阶段。`ERROR` 需先检查错误和残留数据目录；状态结束且线程退出后才允许再次开始。

实现：[2_Data_Collection.py](../pico_piper_streamlit_app/pages/2_Data_Collection.py)、[recorder.py](../pico_piper_streamlit_app/recorder.py)。

## 预览、action 与质量提示

网页实时面板每 **0.5 秒**刷新，展示最近一次图像。录制线程目标为 **30 Hz**；它们不是同一个帧率。用 `loop_dt_ms`、`schedule_lag_ms`、各相机 `age_ms` 和 `valid` 查看实际时序；固定的目标值不能证明实际达到 30 Hz。

`loop_dt_ms` 是逻辑帧时间差，调度重新对齐时会归零；`schedule_lag_ms` 在桥接／相机处理之前测量。它们可能遗漏重新对齐前的长延迟，不能当作完整墙钟耗时或实际吞吐率。评估吞吐时需结合独立测量的录制耗时与实际保存帧数。

录制 action 的关节部分优先使用年龄不超过 500 ms 的有效 IK 目标，否则尝试关节反馈；夹爪独立选择控制值或反馈。松开手柄不会直接触发 hold，仍在年龄窗口内的 IK 目标可以继续被选用。反馈回退没有额外检查反馈年龄；无可用字段时为零，桥接请求异常时短暂使用缓存后为零。详见 [action 选择规则](ARCHITECTURE.md#observations-and-actions)。这些数据值经 no-op `send_action` 返回，实际机械臂仍由 ROS 控制。

单条质量统计只覆盖该条录制期间，不包括重置和等待确认。当前判定规则为：

| 提示 | 条件 |
| --- | --- |
| 错误级提示 | 无统计帧；bridge 有效率 <99%；VR 有效率 <95%；任一路相机或 action semantic 有效率 <99.9% |
| 警告级提示 | 最大调度延迟 >50 ms；任一路相机最大年龄 >80 ms；任一侧 hold 标记比例 >70% |

错误级提示优先显示。这些提示用于人工判断，**不会禁用保存按钮**。`*_action_from_ik/hold` 和 `*_action_semantic_valid` 根据年龄计算，不是完整 action 数据验证或运动保护；例如它们没有同时核对所有夹爪字段与实际回退路径。bridge 响应成功也不等于各路数据新鲜。结合原始年龄、相机、VR 和设备状态决定保存还是重采。

## 结果页的检查范围

输入实际完成的数据集目录；结果页首次打开时的 `/projects/lerobot/NX/test/pico_piper_10_smoke` 是继承的示例路径，仓库不附带该数据集。本会话采集后会优先使用最近的数据路径。

当前 [validate_dataset()](../pico_piper_streamlit_app/dataset_validate.py) 会读取 `meta/info.json`，汇总 `data/chunk-*/*.parquet` 的行数和 episode 数量，展示部分时序／有效性统计，再用 `ffprobe` 获取匹配 MP4 的视频信息。`ffprobe` 必须在服务进程的 `PATH` 中可执行。

顶层 `ok` 只依据现有 `errors` 列表：缺少 `info.json`，或声明图像特征时“视频文件总数不等于图像特征数”，会报失败。没有错误不代表全量完整性校验通过：

- 不强制要求存在 Parquet，不比对元数据总帧数与实际行数，也不逐条核对视频与 episode 覆盖关系。
- 视频数量规则假设每个相机只有一个物理 MP4；合法的多文件／多 chunk 数据也可能被判失败。
- `ffprobe` 非零退出的错误显示在 Videos 表的 `error` 列，未计入顶层 `ok`。缺少可执行文件、损坏 JSON 或无法读取 Parquet 等情况可能直接抛出异常。
- 状态／action 的 shape 和质量统计主要用于展示，不参与完整 schema 校验或质量准入；统计会排除非有限值和 ≥999999 的哨兵值。

因此页面“检查通过”表示当前有限规则未发现错误。交付数据时还需人工核对 episode 数量、元数据与行数、各视频错误、时间统计及实际内容。此次文档对齐保留检查器原有行为。
